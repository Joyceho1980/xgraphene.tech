# Google Prospecting and Email Verification Workflow

Date: 2026-06-09

## Purpose

This workflow defines how XIHE should:

1. find target accounts with Google
2. identify real decision-maker routes
3. verify whether an email path is good enough for outbound use

The goal is not to collect random companies. The goal is to produce contactable accounts with a real reason to care about XIHE.

## Prospecting Principle

Search for business situations, not only industry labels.

Good prospecting starts from:

- service model
- recovery stack
- premium positioning
- buyer type
- geography

not just from:

- "clinic"
- "wellness"
- "rehab"

## Google Search Lanes

Use several different search lanes for the same segment. One lane never gives enough coverage.

### 1. Segment Search

Use direct category words.

Examples:

- `sports medicine clinic "physical therapy" "recovery" usa`
- `orthopedic clinic "sports medicine" "performance recovery"`
- `recovery center cryotherapy infrared red light compression`
- `integrative clinic longevity recovery far infrared`

### 2. Geography + Segment Search

Use city, state, metro, or country filters.

Examples:

- `site:.com "sports medicine" "Austin" "physical therapy"`
- `"recovery center" "Miami" cryotherapy red light`
- `"physical therapy" "New York" sports rehab premium`
- `"longevity clinic" "Dubai" recovery wellness`

### 3. Modality Stack Search

This is one of the best lanes. Search for companies already selling related services.

Examples:

- `"cryotherapy" "red light" "compression" "infrared sauna"`
- `"recovery lounge" PEMF red light cold plunge`
- `"sports recovery" hyperbaric red light cryotherapy`
- `"wellness center" IV therapy red light recovery`

Why it works:

- if they already sell recovery modalities, they understand the category
- they are easier to position for XIHE than cold educational buyers

### 4. Premium Signal Search

Look for high-ticket operators.

Examples:

- `"concierge physical therapy" sports medicine`
- `"executive health" recovery wellness clinic`
- `"luxury wellness resort" recovery spa longevity`
- `"performance lab" recovery suite`

Signals to watch:

- multi-location
- executive health
- athlete partnerships
- concierge service
- recovery membership
- high-end interiors or hospitality language

### 5. Role-Based Search

Search for actual internal routing paths.

Examples:

- `site:companydomain.com CEO`
- `site:companydomain.com founder`
- `site:companydomain.com "practice administrator"`
- `site:companydomain.com "director of operations"`
- `site:companydomain.com "partnerships"`
- `site:companydomain.com "business development"`
- `site:companydomain.com contact`

### 6. Contact-Route Search

Search for the pages that tell us how the company wants inbound requests routed.

Examples:

- `site:companydomain.com contact`
- `site:companydomain.com locations`
- `site:companydomain.com team`
- `site:companydomain.com leadership`
- `site:companydomain.com partnerships`
- `site:companydomain.com vendors`

### 7. LinkedIn-Supported Search

Use Google to find LinkedIn pages when direct site navigation is weak.

Examples:

- `site:linkedin.com/in "company name" founder`
- `site:linkedin.com/in "company name" "operations"`
- `site:linkedin.com/company "company name"`

Use this for role discovery, not as the only source of truth.

## Search Sequence

Run this order for each segment:

1. segment search
2. geography + segment search
3. modality stack search
4. premium signal search
5. role-based search on shortlisted accounts
6. contact-route search on shortlisted accounts

Do not do deep role research on weak-fit accounts.

## What Makes an Account Worth Keeping

Keep the account if most of these are true:

- already sells recovery, rehab, wellness, or performance services
- has a premium or multi-service positioning
- has enough scale for a paid installation
- has a visible contact path
- has a clear XIHE story: differentiation, service expansion, recovery room, or premium patient experience

Drop the account if most of these are true:

- only consumer commodity retail
- weak budget fit
- no visible recovery use case
- no identifiable routing path
- hypersensitive regulatory environment for first-touch outreach

## Account Capture Fields

When adding a prospect, capture:

- company name
- website
- country
- city
- segment
- public services / modality stack
- pain hypothesis
- XIHE angle
- decision maker
- position
- email path
- phone
- contact form
- source links
- next action

## Email Verification Principle

Do not treat every visible email as valid just because it exists.

Use a confidence ladder:

1. real person confirmed
2. role mailbox with clear routing value
3. generic inbox
4. no email, only form or phone

## Email Verification Ladder

### Level 1. Source Check

Best sources:

- official website
- official contact page
- official team or leadership page
- official press release or bio page

Weaker sources:

- scraped directories
- third-party list sites
- guessed emails with no supporting evidence

### Level 2. Pattern Check

If no direct email is shown, infer the pattern from the company domain.

Common patterns:

- `firstname@domain.com`
- `firstname.lastname@domain.com`
- `firstinitiallastname@domain.com`

Only keep a guessed email if:

- the domain is correct
- the role is plausible
- the pattern matches other visible emails from the same domain

### Level 3. Domain Check

Before using the email, check:

- does the website domain resolve
- does the domain have MX records
- does the email domain match the company domain

If the contact email uses a different domain, note why.

### Level 4. Route Quality Check

Ask:

- is this a named person
- is this operations or partnerships
- is this a clinic front desk
- is this a generic inbox

Use named person first.

### Level 5. Send Readiness

An email is launch-ready if one of these is true:

- named person + plausible pattern or direct publication
- named role mailbox with clear business routing
- generic inbox used only to test workflow and clearly labeled as backup

## Verification Outcomes

Use these statuses in notes or CRM:

- `Verified Direct` - official and named
- `Verified Role` - official role-based inbox
- `Backup Generic` - official but generic inbox
- `Pattern Inferred` - guessed from pattern, not yet confirmed
- `Form Only` - no usable email, use contact form
- `Phone Route` - no usable email, call for routing

## Practical Email Decision Rules

- If we have `Verified Direct`, send.
- If we have `Verified Role`, send if the role is relevant.
- If we only have `Backup Generic`, use it only for process testing or as a backup touch.
- If we only have `Pattern Inferred`, try to confirm before sending.
- If we only have `Form Only` or `Phone Route`, do not pretend the account is email-ready.

## Google Queries for Email Discovery

Use these only after the account is already qualified.

- `site:companydomain.com "@companydomain.com"`
- `site:companydomain.com contact "@companydomain.com"`
- `site:companydomain.com team "@companydomain.com"`
- `site:companydomain.com leadership "@companydomain.com"`
- `"company name" "@companydomain.com"`
- `"firstname lastname" "@companydomain.com"`

## Workflow Summary

1. Find the account through business-fit search
2. Confirm service model and XIHE fit
3. Find role path
4. Find contact route
5. Classify email confidence
6. Write pain-point-led outreach
7. Save into CRM with clear route quality notes

## Important Reminder

The real target is not "more emails."

The real target is:

- better accounts
- better routing
- better reply probability
