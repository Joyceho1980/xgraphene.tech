# Decision: Keyword Section Hybrid Architecture

Date: 2026-06-11

## Decision

XIHE should use a hybrid architecture for the future `Keyword Section`.

Do not choose only:

- Google AI Studio plus n8n

or only:

- full local codebase

Use both, with clear responsibility boundaries.

## Recommended Architecture

### 1. Logic layer

Use:

- Gemini or GPT prompts
- local keyword engine rules

Purpose:

- keyword clustering
- intent classification
- angle suggestion
- structured output generation

### 2. Workflow layer

Use:

- n8n

Purpose:

- connect Gmail
- connect CRM
- connect search inputs
- connect AI model calls
- orchestrate writeback and triggers

### 3. UI and visualization layer

Use:

- local custom dashboard

Purpose:

- keyword heatmap
- strategy matrix
- keyword flow
- campaign trigger panels
- XIHE-branded operator experience

## Why This Is The Right Split

### n8n strengths

- speed
- visual orchestration
- easy API chaining
- easier troubleshooting

### Local dashboard strengths

- full visual control
- better charting and interaction
- deeper XIHE branding
- room for advanced CRM integration

### AI model strengths

- clustering
- interpretation
- topic expansion
- angle generation

## Keyword Section Rule

The `Keyword Section` should be treated as a local API-backed module.

That means:

- inputs can come from AI Studio, manual input, or n8n
- structured keyword outputs should be generated by a stable internal API
- the visual module should read from this structured layer rather than raw prompt text

## Production Rule

The workflow should be:

1. manual and prompt-driven first
2. local API wrapper second
3. n8n orchestration third
4. visual dashboard on top

This reduces risk and avoids over-automation too early.

## XIHE Conclusion

For XIHE, the best production path is:

- AI Studio for model tuning
- n8n for orchestration
- local API and dashboard for control and visualization

This gives XIHE both speed and ownership.
